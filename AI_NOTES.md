# Как шла работа с AI (5–7 строк)

1. **Шаги.** Задача разбита так: обзор всех 48 строк и каталог форматов (телефоны, даты, имена, дубли) → правила нормализации, спорные случаи зафиксированы явно → CLI-скрипт → тесты → второй, специально «грязный» файл той же структуры → сверка чисел → README.
2. **Что поручено агенту (Claude Code).** Исполнение целиком: разбор данных, правила, код, тесты, генерация второго файла. В ТЗ агенту заданы порядок шагов, запрет хардкода под конкретные строки и обязательная проверка: сверить «вход = чистые + дубли + проблемные» и прогнать скрипт на другом файле.
3. **Где агент ошибся.** В первом прогоне перепутал день и месяц: получилось 11 / 14 / 23 вместо 22 / 14 / 12, ошибку поймала сверка с независимым подсчётом. Правило «дата не в будущем» могло молча превратить 10.11.2026 в 11 октября, поэтому даты через точку теперь всегда читаются как ДД.ММ. Регулярка для «2026 г.» ломала «1 авг», а в собственных тестах агента нашлись ошибки (`ws.save` вместо `wb.save`).
4. **Как проверено.** 156 тестов pytest. Отдельный скрипт пересчитал телефоны без функций основного, числа сошлись. Для второго файла (41 строка) ожидаемый результат задан по каждой строке. Повторный прогон на собственном clean ничего не меняет. Вне сессии агента результат перепроверен ещё раз: запуск из командной строки и просмотр всех 12 проблемных строк.
5. **Осознанные решения.** Номер 8-800 считается линией организации, а не телефоном клиента: у пяти разных людей он один и тот же. Если у одного номера разные имена, строки склеиваются по правилу задания, но с пометкой «проверьте». Из дублей остаётся самая ранняя заявка.

Запись сессии: `ai_session/session.md` (читаемый вид), `ai_session/session.jsonl` (исходник). В путях имя пользователя заменено на «[скрыто]», остальное не правилось.
