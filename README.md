# Чистка файла заявок

`clean_zayavki.py` — CLI-скрипт: берёт xlsx с колонками **Имя, Телефон, Дата заявки, Источник**
и выдаёт чистый файл, список проблемных строк с причиной и отчёт об удалённых дублях.
Правила общие, под конкретные строки ничего не подогнано: скрипт рассчитан на любой файл той же структуры.

## Установка и запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python clean_zayavki.py zayavki.xlsx -o output
.venv/bin/python -m pytest -q          # тесты (156 шт.)
```

Подойдёт любой Python 3.10+ с `openpyxl` (Windows: `.venv\Scripts\python`). При разработке системный `python3` 3.14 из Homebrew
оказался сломан (не грузится `pyexpat`), поэтому venv делался на 3.12.

Состав архива: скрипт и тесты, `output/` — результат по `zayavki.xlsx`, `output_test2/` — по второму тестовому файлу,
`ai_session/` — запись работы с AI-агентом, `AI_NOTES.md` — как шла работа (5–7 строк).

Параметры (`--help`):

| параметр | что делает |
|---|---|
| `input` | входной .xlsx |
| `-o / --out-dir` | папка результатов (по умолчанию `output` рядом со входным файлом) |
| `--clean / --problems / --duplicates` | явные пути к выходным .xlsx (рядом пишется .csv с тем же именем) |
| `--sheet` | лист (по умолчанию первый) |
| `--today ГГГГ-ММ-ДД` | «сегодня» для проверки дат в будущем (по умолчанию текущая дата) |
| `--csv-sep` | разделитель CSV (по умолчанию `;` — русский Excel открывает такой CSV двойным кликом; кодировка UTF-8 с BOM) |

## Что получается на выходе

| файл | содержимое |
|---|---|
| `clean.xlsx` / `.csv` | уникальные записи без проблем: Имя, Телефон, Дата заявки, Источник + **Строка** (номер строки в исходнике, заголовок = 1) + **Примечание** (что склеено, как прочитана неоднозначная дата и т.п.) |
| `problems.xlsx` / `.csv` | проблемные строки: нормализованные значения, **Причина**, исходные значения ячеек (чтобы поправить руками) |
| `duplicates.xlsx` / `.csv` | удалённые дубли: какая строка оставлена вместо них и почему |

Каждая входная строка попадает **ровно в один** из трёх файлов. Скрипт печатает сверку:
`входных строк = чистых + дублей + проблемных`. Полностью пустые строки пропускаются, их число тоже печатается.

**На `zayavki.xlsx`: 48 строк → 22 чистых + 14 дублей + 12 проблемных.**
Проблемные: 8 без телефона (из них 5 с номером 8-800), 3 с битой датой, 1 без имени.

## Правила

### Телефон → `+7XXXXXXXXXX`
1. Из ячейки берутся куски, похожие на номер: цифры, разделённые пробелами, дефисами, скобками и точками.
   Текст вокруг отбрасывается («тел.: 8 917 400 52 19 (после 18:00)» → `+79174005219`).
   Короткие числа (< 5 цифр: «18:00», «доб. 45») номером не считаются.
   Если номеров несколько, берётся первый корректный, и об этом пишется примечание.
2. Число в ячейке Excel (`89032218840`, `8.9E10`) обрабатывается так же, как текст.
3. 11 цифр, начинающихся с `8` или `7` (с плюсом или без), → `+7` и последние 10 цифр.
4. 10 цифр без кода страны: `9xx` (мобильный), `3xx`/`4xx`/`80x–87x` (коды регионов и служб) → `+7` + 10 цифр.
   `7…`, `88…`, `89…` из 10 цифр — это `7`/`8` плюс номер с пропущенной цифрой → проблема «не хватает цифры».
5. Всё остальное — **«нет телефона»** с уточнением в «Причине»:
   пусто; не номер («не знаю», «abc»); не хватает или лишние цифры; иностранный код (`+44…`);
   несуществующий код (`+7 0xx`, `1xx`, `2xx`, `5xx`, `6xx`); заглушка из одинаковых цифр (`+7 999 999-99-99`);
   **номер 8-80X** (см. спорные случаи).
6. Добавочный номер («доб. 45», «ext», «#») отбрасывается с пометкой: в формат `+7XXXXXXXXXX` он не помещается.

### Дата → `ГГГГ-ММ-ДД`
- Настоящая дата Excel (ячейка-дата) берётся как есть, время отбрасывается.
- Excel-дата числом (`46268` → 2026-09-03), в том числе сохранённая текстом.
- `ГГГГ-ММ-ДД`, `ГГГГ/ММ/ДД`, `ГГГГ.ММ.ДД`.
- `ДД.ММ.ГГГГ`, `ДД-ММ-ГГГГ`, `ДД/ММ/ГГГГ`, `ММ/ДД/ГГГГ` (порядок см. ниже), год из двух цифр: `26` → `2026`.
- Месяц словом: «6 сентября 2026», «5 авг. 2026 г.», «1 сент 2026г.», «Aug 10, 2026».
- Хвост со временем («24.09.2026 14:35», «…T14:30:00») отбрасывается.
- **Битая дата** (в проблемные, строка не теряется): пусто; не распознана («хх.09.2026»);
  нет года («12 сентября»); несуществующая («31.02.2026»); **в будущем** относительно `--today`;
  раньше 2000 года.

### Имя
- Убираются невидимые символы (zero-width space, BOM, мягкий перенос); неразрывные пробелы и табы
  становятся обычными пробелами; повторные пробелы схлопываются, края обрезаются.
- Каждое слово и каждая часть через дефис пишутся с заглавной: «ПАВЛОВА ирина» → «Павлова Ирина»,
  «анна-мария» → «Анна-Мария». Инициалы сохраняются («К. Белоусов»). Буква «ё» сохраняется.
- Латинские буквы-двойники внутри русских слов заменяются кириллицей («Пeтров» с латинской `e` → «Петров»).
  Иначе такой «Петров» не совпал бы с настоящим. Полностью латинские имена («John Smith») не трогаются.
- **Нет имени**: пусто, нет ни одной буквы («-», «123») или заглушка («нет», «не указано», «N/A»).
- Порядок «Имя Фамилия» / «Фамилия Имя» не меняется: надёжно отличить имя от фамилии без словаря нельзя.

### Источник
Пробелы обрезаются, значение приводится к нижнему регистру («Сайт » → «сайт»), как в исходном файле.

### Дубли: какая запись остаётся
Дубль — одинаковый **нормализованный** телефон (`8 (916) 245-17-83` = `+7 916 245 17 83` = `79162451783`).
Строки без телефона ни с чем не склеиваются. Из группы остаётся **одна** запись, поля не смешиваются.
Порядок выбора:
1. **Запись без проблем** важнее записи с проблемой. Если первая заявка без имени, а вторая полная,
   остаётся полная, и человек попадает в чистый файл.
2. **Самая ранняя дата заявки.** Это первое обращение: дата и источник первого касания важны для
   атрибуции канала, а повторные заявки — повторные касания.
3. **Более полное имя** (меньше инициалов): «Белоусов Кирилл» вместо «К. Белоусов».
4. Строка выше в файле.

Остальные строки группы уходят в `duplicates.xlsx` с номером оставленной строки, у оставленной в
«Примечании» перечислены её дубли. Если у всех строк группы есть проблемы, одна запись идёт в
проблемные, остальные — в дубли (с пометкой, что у них тоже есть проблема).

## Спорные случаи: как решены

| случай | решение | почему |
|---|---|---|
| `8…` vs `+7…` vs `7…` | всё → `+7` + 10 цифр | это один и тот же номер в разной записи |
| номер без кода (10 цифр) | `+7` + 10 цифр, если код правдоподобный (`9xx`, `3xx`, `4xx`, `80x–87x`) | иначе это обрезанный номер |
| лишние / недостающие цифры | «нет телефона», исходник сохраняется в problems | угадывать, какую цифру убрать или добавить, нельзя: телефон — ключ дедупликации |
| добавочный | отбрасывается, с примечанием | формат `+7XXXXXXXXXX` его не вмещает |
| **8-800 (и весь 8-80X)** | «нет телефона: сервисная линия организации», строки **не склеиваются** | в исходнике 5 **разных** людей (стр. 19–23) с одним 8-800 7074619 — похоже, записан номер горячей линии, а не клиента. Это бесплатный номер организации: перезвонить по нему конкретному человеку нельзя. Если считать его телефоном, 4 из 5 людей молча пропали бы как «дубли» |
| один номер, **разные имена** (Морозова Елена / Белов Никита, стр. 8–9) | по правилу задания склеиваются, но с пометкой «другое имя — проверьте» в clean и в duplicates | заказчик задал «одинаковый номер = один человек»; при этом конфликт не прячется. Похожие имена (перестановка слов, ё/е, инициал) конфликтом не считаются |
| `ДД.ММ` vs `ММ/ДД` | точка и дефис — всегда ДД.ММ (русская запись). С «/» встречаются оба порядка, поэтому неоднозначная дата (обе части ≤ 12) решается так: **1)** если у этого источника все однозначные «/»-даты записаны одним порядком, берётся этот порядок (в исходнике «сайт» пишет `09/16`, `09/24`, то есть ММ/ДД, а «telegram» пишет `17/09`, `22/09`, то есть ДД/ММ); **2)** если один вариант невозможен (в будущем), берётся другой; **3)** вариант, ближайший к медиане остальных дат файла; **4)** ДД/ММ | так `09/03/2026` с сайта читается как 3 сентября, и это совпадает с `03.09.2026` того же человека. Как была прочитана дата, пишется в «Примечание» |
| двузначный год | `26` → `2026` | заявок из 1900-х не бывает |
| дата без года («12 сентября») | битая дата | год угадывать не стали: скрипт запускают на других файлах |
| будущая дата (`19.09.2062`) | битая дата, **без автоисправления** | скорее всего опечатка 2026, но «переставить цифры» — догадка |
| `10.11.2026`, когда 10 ноября ещё не наступило | битая дата, **не** переворачивается в 11 октября | для записи через точку порядок ДД.ММ надёжнее, чем «влезает в диапазон» |
| Excel-даты числом | дни от 1899-12-30, допустимый диапазон 2000–2099 | стандартная система дат Excel |
| дубль, у которого проблема только в нём самом (стр. 16 «12 сентября») | уходит в дубли, в проблемные не попадает | человек уже представлен оставленной строкой |

## Проверка
- `tests/test_clean_zayavki.py` — 156 тестов:
  - нормализация всех форматов телефонов, дат и имён (все варианты из исходника плюс дополнительные);
  - разрешение неоднозначных дат и выбор оставляемой записи;
  - прогон на исходном файле со сверкой 22 / 14 / 12, проверкой, что каждая строка 2–49 попала ровно
    в один файл, и проверкой конкретных решений;
  - прогон на сгенерированном файле;
  - перепутанный порядок колонок, лишняя колонка и строка-заголовок над таблицей;
  - повторный прогон на собственном `clean.xlsx` ничего не меняет;
  - ошибки ввода (нет файла, нет заголовков → код возврата 2).
- `tests/make_test_file.py` генерирует **другой** файл `tests/data/zayavki_test2.xlsx` (41 строка,
  одна из них пустая), на каждую строку задан ожидаемый результат. Итог: 40 → 18 чистых + 4 дубля + 18 проблемных.
  Результат прогона лежит в `output_test2/`.
